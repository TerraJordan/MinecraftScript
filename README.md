# Minecraft Click Bot

Лёгкий скрипт для автоматизации рутинных 2D-действий (клики + движение) в окне лицензионного клиента Minecraft. Запускается по расписанию — строго в хх:30 по времени Europe/Moscow.

Используй только на серверах, где автоматизация подобного рода разрешена правилами.

## Состав проекта

- `app.py` — **единое GUI-приложение**: вкладка «Настройка сценариев» (редактор шагов, ручная запись, расписание, горячие клавиши, диагностика) и вкладка «Запуск» (старт/стоп бота, статус, лог в реальном времени).
- `settings.py` — загрузка/сохранение `settings.json` (хоткей + расписание) и расчёт момента срабатывания.
- `hotkey.py` — глобальная горячая клавиша старта/остановки (реагирует только на заданную комбинацию, ничего не логирует).
- `diagnostics.py` — 5 пассивных проверок готовности («Проверить готовность» в GUI).
- `config_gui.py` — прежний отдельный редактор сценариев (v2), оставлен для совместимости.
- `recorder.py` — модуль **ручной** записи шагов (см. пояснение ниже — это не кейлоггер).
- `picker.py` — вывод координат курсора в реальном времени (для калибровки кликов).
- `movement.py` — модуль эмуляции клавиатуры (удержание клавиш, ввод текста в чат).
- `scenario_chat.json` — **Сценарий 1**: сообщение в чат + ожидание 60 сек.
- `scenario_movement.json` — **Сценарий 2**: шаги движения/кликов + открытие встроенного инструмента поиска.
- `scenario.json` — общий формат из v2, `bot.py` его больше не использует напрямую, оставлен как шаблон.
- `bot.py` — основной бот: в каждом цикле сначала выполняет Сценарий 1, при неудаче автоматически переходит к Сценарию 2; расписание читается из `settings.json`.
- `settings.json` — создаётся автоматически при первом сохранении настроек в GUI (хоткей, расписание).
- `template.png` — картинка-шаблон элемента интерфейса (готовится вручную, см. ниже).
- `tests/` — автотесты на `pytest` (парсинг сценариев, расчёт расписания, логика выбора сценария).
- `requirements.txt` — зависимости.
- `bot_log.txt` — создаётся автоматически.

## О рекордере: почему это НЕ кейлоггер

В задании упоминался рекордер с «глобальным хуком» на клавиатуру и мышь — то есть фоновым перехватчиком, который слушает весь ввод в системе независимо от того, что делает пользователь. Такой компонент не был реализован, потому что технически это кейлоггер: он не отличает «игрок жмёт W в Minecraft» от «пользователь вводит пароль в другом окне», и специально исключён из проекта.

Вместо этого `recorder.py` работает только через **явные, разовые действия** в GUI:

- Чтобы записать удержание клавиши — нажми «Начать удержание», подожди нужное время, нажми «Закончить удержание». Время между двумя твоими нажатиями кнопок и становится длительностью шага.
- Чтобы записать клик — наведи курсор в окно игры, впиши координаты (или подсмотри их через `picker.py`) и нажми «Отметить клик».

Никакого фонового слежения за вводом нет — запись идёт, только пока ты сам явно нажимаешь кнопки в самом приложении.

## Почему pynput, а не pyautogui для клавиатуры

Для кликов мышью по-прежнему используется `pyautogui` (как в v1) — менять не было причин. А вот для удержания клавиш выбран `pynput`, потому что:

- `pynput.keyboard.Controller` даёт раздельные `press()`/`release()` без встроенной внутренней паузы, которую `pyautogui` добавляет между каждым вызовом (`pyautogui.PAUSE`). Это мешало бы точно выдерживать «зажать ровно N мс».
- Разделение ответственности получается чище: `movement.py` целиком отвечает за клавиатуру (через pynput), а клики остаются в `bot.py` через pyautogui, как и раньше.

Если по какой-то причине понадобится вернуться к pyautogui для клавиш — это осознанная смена библиотеки, и её стоит обсудить отдельно, так как код в `movement.py` придётся переписать.

## 2. Подготовка template.png

Это скриншот того элемента интерфейса, который должен появиться после кликов (например, кнопка, окно подтверждения, значок).

1. Разверни Minecraft в окне и доведи игру до состояния, когда нужный элемент виден на экране.
2. Сделай скриншот всего экрана любым удобным способом (Print Screen, ножницы Windows, и т.д.).
3. Обрежь скриншот так, чтобы остался **только сам элемент** (небольшой, но узнаваемый фрагмент — кнопка, иконка, надпись). Чем компактнее и контрастнее фрагмент, тем надёжнее сработает распознавание.
4. Сохрани обрезанное изображение как `template.png` в этой же папке, рядом с `bot.py`.

Если файла `template.png` не будет — бот не упадёт, а выведет понятное сообщение об ошибке и продолжит работу (просто не сможет подтвердить успех клика).

## 3. Подготовка шаблона и калибровка координат

Прежде чем настраивать сценарии в `app.py`, подготовь `template.png` (см. выше) и, если нужно, воспользуйся `picker.py` для получения координат кликов (см. шаг 6 ниже) — это делается один раз перед основной настройкой.

## 4. Работа через app.py (рекомендуется в v3)

Запусти единое приложение:

```bash
python app.py
```

**Вкладка «Настройка сценариев»:**
1. В поле «Файл сценария» укажи, что редактируешь — `scenario_movement.json` (Сценарий 2) или любой другой файл (например, свой черновик). `scenario_chat.json` (Сценарий 1) обычно достаточно отредактировать только по полю «Резервное/чат-сообщение» — шагов движения там не требуется.
2. Добавляй шаги вручную («Добавить шаг вручную») или через ручную запись:
   - **Удержание клавиши**: впиши клавишу, нажми «Начать удержание», подожди нужное время, нажми «Закончить удержание» — шаг `key_hold` добавится в список с реальной измеренной длительностью.
   - **Клик**: наведи курсор в окно Minecraft, посмотри координаты через `picker.py` (см. ниже), впиши их в поля X/Y и нажми «Отметить клик».
3. Для Сценария 2 **последним шагом** сделай открытие встроенного инструмента поиска — это может быть клик по нужной кнопке или (через «Добавить шаг вручную») удержание клавиши, которая открывает нужное окно/инструмент в игре.
4. Нажми «Сохранить» (перезаписывает текущий файл) или «Сохранить как...» для нового файла.

**Вкладка «Запуск»:**
- Кнопка «Старт» запускает `bot.py` как отдельный процесс (GUI не блокируется и не участвует в ожидании хх:30).
- Кнопка «Стоп» останавливает процесс бота.
- Внизу в реальном времени (обновление раз в 2 секунды) показываются последние строки `bot_log.txt`.

Старый отдельный `config_gui.py` по-прежнему работает так же, как в v2, если вкладка «Запуск» не нужна.

## 5. Как устроены два сценария и переход между ними

При каждом срабатывании хх:30 бот выполняет сценарии по порядку:

1. **Сценарий 1 (`scenario_chat.json`)** — отправляет сообщение в игровой чат (поле `chat_fallback_message`), ждёт ровно 60 секунд, проверяет `template.png`.
2. Если элемент **не найден** — это **автоматически**, без участия пользователя, в том же цикле хх:30 запускает **Сценарий 2 (`scenario_movement.json`)**: выполняет шаги `key_hold`/`mouse_click` по порядку (с паузой ≥50 мс между действиями), последним шагом открывает встроенный инструмент поиска, проверяет шаблон, при неудаче повторяет весь сценарий до 3 попыток.
3. Переход между сценариями всегда фиксируется отдельной строкой в `bot_log.txt` вида:
   ```
   [... МСК] Сценарий 1 не удался (точность 0.42) → запуск Сценария 2.
   ```
4. Итоговый результат (успех одного из сценариев или финальная неудача обоих) тоже логируется.

Формат `bot_log.txt` не менялся — только добавились новые типы строк для этого перехода и разделения по сценариям.

## 6. Калибровка координат кликов через picker.py

Координаты кликов в сценарии должны быть заданы **относительно левого верхнего угла окна Minecraft**, а не всего экрана. Порядок:

1. Запусти `bot.py` один раз (или дождись его первого срабатывания) — в консоли он напечатает строку вида:
   ```
   [+] Окно найдено в координатах: X=700, Y=200
   ```
   Это и есть левый верхний угол окна игры (`win_x`, `win_y`).

2. Отдельно (в любое время) запусти калибровщик:
   ```bash
   python picker.py
   ```
   Наведи курсор на нужную кнопку/элемент в окне Minecraft и посмотри, какие координаты он показывает (это **абсолютные** координаты экрана). Останови скрипт через `Ctrl+C`.

3. Вычти координаты окна из абсолютных координат курсора:
   ```
   относительная_X = абсолютная_X − win_x
   относительная_Y = абсолютная_Y − win_y
   ```
   Например, если курсор показал `(930, 560)`, а окно начинается в `(700, 200)`, то относительные координаты будут `(230, 360)`.

4. Впиши получившиеся координаты в `app.py` (или `config_gui.py`) при добавлении шага-клика.

## 7. Запуск бота напрямую из консоли (без GUI)

```bash
python bot.py
```

Скрипт будет работать в фоне и ждать наступления минуты `:30` по московскому времени (независимо от часового пояса твоей системы). При каждом наступлении этого момента он:

1. Найдёт и развернёт окно Minecraft (по заголовку `MINECRAFT_WINDOW_TITLE` в начале `bot.py`).
2. Выполнит **Сценарий 1** (`scenario_chat.json`): отправит сообщение в чат, подождёт 60 секунд, проверит `template.png`.
3. Если элемент найден — залогирует успех Сценария 1 и на этом цикл завершится.
4. Если не найден — залогирует переход и **автоматически** выполнит **Сценарий 2** (`scenario_movement.json`): шаги `key_hold`/`mouse_click` строго по порядку (пауза ≥50 мс между действиями), с повтором всего сценария до 3 попыток при неудаче.
5. Залогирует итоговый результат — успех одного из сценариев или финальную неудачу обоих — в `bot_log.txt` с точностью совпадения и временем по МСК.

Чтобы остановить бота — закрой консоль, нажми `Ctrl+C`, либо (если бот был запущен из `app.py`) нажми там кнопку «Стоп».

## v4: исправление бага запуска, хоткей, гибкое расписание, диагностика, тесты

### Что было исправлено

Кнопка «Старт» во вкладке «Запуск» раньше перенаправляла вывод `bot.py` в `DEVNULL`. Если бот падал сразу при запуске (например, из-за отсутствующей библиотеки, битого JSON или отсутствующего окна Minecraft), ошибка терялась молча, а GUI не показывал вообще никакой реакции. Теперь:
- статус сразу меняется на «Запускается…» по нажатию кнопки;
- вывод ошибок (stderr) бота пишется во временный файл и проверяется примерно через 1.5 секунды после старта;
- если процесс к этому моменту уже завершился — ошибка выводится и во всплывающем окне, и строкой в `bot_log.txt`, а не пропадает.

### Горячая клавиша старта/остановки

Во вкладке «Настройка сценариев», секция «Горячие клавиши»:
1. Нажми «Назначить...», затем нажми желаемую комбинацию клавиш (например, `Ctrl+Alt+S`) — она автоматически распознается и появится в поле.
2. Нажми «Сохранить хоткей» — комбинация сохранится в `settings.json` и сразу станет активна.
3. Хоткей работает глобально (даже когда фокус на игре) и переключает бота (старт/стоп).

**Важно про механизм**: хоткей использует `pynput`, но реагирует **только** на заданную комбинацию — он не записывает и не анализирует остальной ввод. Это принципиально отличается от фонового кейлоггера (см. пояснение про `recorder.py` выше) — по сути, это тот же механизм, что в push-to-talk программах или менеджерах хоткеев.

### Гибкое расписание

Раньше периодичность («каждый хх:30») была зашита в код. Теперь в секции «Расписание»:
- **«Строго в минуту часа»** — как раньше, например `30` → бот срабатывает в хх:30 каждого часа.
- **«Каждые N минут»** — например `15` → бот срабатывает на 00, 15, 30, 45 минуте каждого часа.

Нажми «Сохранить расписание» — настройка попадёт в `settings.json`, и `bot.py` подхватит её на следующей проверке (расписание перечитывается на каждой итерации цикла, без перезапуска бота). Часовой пояс остаётся Europe/Moscow независимо от режима.

### Самопроверка готовности

Кнопка «Проверить готовность» в секции «Диагностика» прогоняет 5 пассивных проверок (ничего не кликает и не трогает игру):
1. Найдено ли окно Minecraft по заданному заголовку.
2. Существует и читается ли `template.png`.
3. Валидны ли `scenario_chat.json` и `scenario_movement.json`.
4. Корректно ли читается `settings.json`.
5. Импортируются ли без ошибок нужные библиотеки.

Результат выводится в GUI (✅/❌ по каждому пункту) и дублируется строкой в `bot_log.txt`.

### Автотесты

В папке `tests/` — юнит-тесты на `pytest`, не требующие запущенной игры:
- `test_scenarios.py` — парсинг и валидация JSON-файлов сценариев.
- `test_schedule.py` — расчёт срабатывания по Europe/Moscow для обоих режимов расписания.
- `test_scenario_selection.py` — логика перехода между Сценарием 1 и Сценарием 2 (проверка шаблона мокается, реальных кликов/нажатий нет).

Запуск:
```bash
pip install -r requirements.txt
pytest tests/ -v
```

> На Linux для запуска тестов также нужен виртуальный дисплей (`Xvfb`/`xvfb-run`), так как некоторые библиотеки (`pyautogui`) требуют дисплей при импорте, а `pygetwindow` вообще не поддерживает Linux — в `tests/conftest.py` для него на этот случай подставлена заглушка. На реальной машине с Windows, где будет работать бот, всё это не требуется — там используются настоящие библиотеки.

### Обновлённый визуальный стиль

`app.py` теперь использует единую тёмную палитру (акцентный синий на тёмном фоне), поля сгруппированы по секциям («Сценарий», «Шаги сценария», «Расписание», «Горячие клавиши», «Диагностика», «Статус»), а статус бота во вкладке «Запуск» показывается цветным индикатором (серый — остановлен, жёлтый — запускается, зелёный — работает, красный — ошибка).



Все они находятся в начале файла `bot.py`:

| Параметр | Что делает |
|---|---|
| `MINECRAFT_WINDOW_TITLE` | Точный заголовок окна игры — должен совпадать с тем, что видно в шапке окна Minecraft |
| `CLICKS_SEQUENCE` | Список координат кликов (см. калибровку выше) |
| `CONFIDENCE_THRESHOLD` | Насколько точно должен совпасть шаблон (0.8 обычно достаточно; повышай, если ловятся ложные срабатывания) |
| `MAX_RETRIES` | Сколько дополнительных попыток делать, если элемент не найден с первого раза |
| `ACTION_DELAY_RANGE` | Диапазон случайной паузы между действиями сценария (нижняя граница не может быть меньше 50 мс) |
| `CHAT_FALLBACK_WAIT_SECONDS` | Сколько секунд ждать после отправки резервного сообщения в чат перед финальной проверкой (по умолчанию 60) |

Сам сценарий (какие клавиши/клики выполнять и что писать в чат при неудаче) правится не здесь, а через `config_gui.py` → `scenario.json`.

## Системный трей (v4.1)

Приложение (`app.py`) теперь можно свернуть в системный трей вместо полного закрытия:

- Кнопка **«Свернуть»** во вкладке «Запуск» прячет окно в трей.
- Крестик окна тоже сворачивает в трей (если трей поднялся), а не завершает процесс — это позволяет боту продолжать работать по расписанию, пока окно не видно.
- Иконка в трее (синий кружок с «M») открывает контекстное меню:
  - **«Показать окно»** — разворачивает приложение (также срабатывает по двойному клику на иконке).
  - **«Запустить бота» / «Остановить бота»** — подпись меняется в зависимости от текущего состояния.
  - **«Выход»** — полностью завершает приложение (это единственный способ закрыть его насовсем, кроме `Ctrl+C` в консоли).

Трей использует `pystray`, который сам выбирает подходящий бэкенд под операционную систему (на Windows — через системный API трея). Если `pystray`/`Pillow` не установлены или трей по какой-то причине не поднимается, приложение просто работает как раньше — крестик закрывает окно полностью, кнопка «Свернуть» в этом случае сворачивает окно, но не в трей, а как обычное сворачивание.

## Диагностика

- **"Окно с заголовком ... не найдено"** — проверь `MINECRAFT_WINDOW_TITLE`, он должен точно совпадать с заголовком окна (без лишних пробелов).
- **"Файл шаблона не найден"** — убедись, что `template.png` лежит в той же папке, что и `bot.py`.
- **Клики попадают не туда** — окно игры могло сдвинуться или измениться в размере; либо перекалибруй координаты через `picker.py`, либо просто запусти игру в одном и том же положении окна каждый раз.

## v5: мониторинг лога игры и системный трей

## v7: события игрового лога, авто-принятие группы, расписание VimeWorld

- `log_monitor.py` теперь распознаёт события по настраиваемым regex-паттернам
  (settings.json → log_monitor.patterns, редактируются на вкладке
  «Мониторинг лога»): приглашение в группу (+ команда /party join),
  подземелья трёх сложностей, дикий рейд. Строки-триггеры успеха
  (check_mode) работают параллельно. Антидубль и ротация — без изменений.
- `party_acceptor.py`: авто-принятие приглашений. Основной метод — команда
  из лога отправляется в чат; резервный — OpenCV-клик по template.png;
  экспериментальный — клик по чату (с предупреждением в GUI). Несколько
  приглашений подряд → очередь с уведомлением; таймаут приглашения 60 секунд.
- `scheduler.py`: справочник расписания подземелий/рейдов в GUI + предупреждения
  о событиях вне логов (Тайное лёгкое 16:00, Остров Чеджу 17:00, ДСЛП каждые
  6 часов) за N минут (по умолчанию за 1). Подземелья/рейды уведомляются
  только при фактическом обнаружении в логе.
- `notifier.py`: 10 типов уведомлений (добавлены приглашение, принятие,
  подземелье, рейд, событие расписания).
- GUI: новая вкладка «Мониторинг лога» (путь, тогглы событий, паттерны,
  метод проверки успеха + триггеры, авто-принятие с сегментированным
  переключателем метода); вкладка «Расписание» дополнена справочником
  VimeWorld и настройкой предупреждений.
- Логика сценариев, хоткея, трея, аудита не менялась; старый settings.json
  загружается без ошибок.
